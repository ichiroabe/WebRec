# WebRec

日本語 | [English](README.en.md)

画面操作を記録し、再現可能なスクリプト（Playwright / Puppeteer / JSON）として出力・管理する Chrome 拡張機能（Manifest V3）です。

## 表示言語

日本語と英語に対応しています。管理画面ヘッダーおよびポップアップ右上のセレクタで切り替えられます。初回はブラウザの言語から自動判別し、選択した言語は次回以降も保持されます。

## 機能

- 拡張機能アイコンの「記録を開始」を押すと、その時点で表示していたページの URL を**開始URL**として記録を開始します。
- クリック、テキスト入力、セレクトボックス選択、Enter/Escape キー入力、ページ遷移（SPA の履歴遷移含む）を自動で記録します。
- 記録中はページ右上に「WebRec 録画中」のインジケーターが表示され、そこからも停止できます。
- 「記録を停止して保存」を押すと、記録内容がブラウザ内の IndexedDB に保存されます。
- 管理画面（拡張機能アイコン → 「スクリプト管理を開く」、または拡張機能の「オプション」）から、保存済みの録画を一覧・名前変更・削除できます。
- 各録画は次の形式で出力できます。
  - **Playwright**（`@playwright/test` 形式）
  - **Puppeteer**
  - **JSON**（ステップの生データ）
  - コピー / ファイルダウンロードが可能です。
- 管理画面から「▶ 再生」を押すと、記録した操作を実際に再現します（進捗をステップごとに表示）。再生先は新しいウィンドウか、**ログイン済みなど下準備を済ませた既存のタブ**から選べます。
- 再生 1 回ぶんの結果は**実行ログ**に残ります（どのステップで失敗したか、出たダイアログまで）。
- **⏰ スケジュール**で、毎日この時刻／N分ごとの自動実行を設定できます（ブラウザ起動中のみ）。
- **検証ステップ**（`assertText` / `assertVisible` / `assertMissing`）で、期待と違う画面になったらその場で止められます。

## インストール方法（開発者モードで読み込み）

1. Chrome で `chrome://extensions` を開く
2. 右上の「デベロッパーモード」を ON にする
3. 「パッケージ化されていない拡張機能を読み込む」をクリックし、この `WebRec` フォルダを選択する

## 使い方

1. 記録したいページを開き、拡張機能アイコンをクリックして「● 記録を開始」を押す
2. 通常どおりページを操作する（クリック・入力・遷移など）
3. アイコンを再度開き「■ 記録を停止して保存」を押す、またはページ右上のインジケーターの「■ 停止」を押す
4. 「管理画面で開く」から、保存された録画の一覧・スクリプト出力・再生ができる

## ワンタイムパスワード（2要素認証）

**記録したコードは再生に使えません。** TOTP は30秒で切り替わるため、記録時の数字は再生時には無効です。SMS やメールで届くコードも同様に再現できません。

そこで WebRec は次のように扱います。

1. **記録時**: ワンタイムパスワード欄を自動検出し、値を `<OTP>` としてマスクします（実際のコードは保存しません）。`autocomplete="one-time-code"` を第一に見て、無い場合は `otp` / `totp` / `mfa` / `2fa` / `認証コード` / `ワンタイム` などの語で判定します。
2. **検証**: `<OTP>` のまま残っているとエラーになり、直し方を案内します。
3. **再生時**: `{{totp:シークレット}}` と書いておけば、**その場で正しいコードを計算**します。

```json
{ "type": "input", "selector": "#otp", "value": "{{totp:JBSWY3DPEHPK3PXP}}" }
```

シークレットは認証アプリを登録するときに表示される Base32 の文字列です（QRコードの下に併記されるもの、`otpauth://` URL の `secret=` パラメータ）。小文字・空白・ハイフン区切りのまま貼っても構いません。8桁のシステムでは `{{totp:シークレット|8}}` と書きます。

**書き出した Playwright / Puppeteer スクリプトでも同じように動きます。** Node の `crypto` を使う実装が埋め込まれ、実行のたびに計算されます（RFC 6238 準拠。公式テストベクタで検証済み）。

### 注意

- シークレットは**パスワードと同等の認証情報**です。これがあれば誰でもコードを生成できます。録画データや JSON エクスポートに含まれるため、**テスト用アカウントに限って**使い、エクスポート先の取り扱いにご注意ください。
- 本番アカウントのシークレットを埋め込むことは推奨しません。
- 認証アプリ側の拡張機能（1Password や Authenticator など）がコードを自動入力する場合も、入力された数字は記録されず `<OTP>` になります。上と同じく `{{totp:...}}` に書き換えてください。
- SMS・メール・プッシュ通知による認証は、原理的に再現できません。テスト環境では2要素認証を無効にするか、固定のテスト用コードを使える設定にしてください。

## 再生時のログインセッション

再生の起点は「▶ 再生」を押したあとのダイアログで選べます。

| 再生先 | 動き |
| --- | --- |
| **新しいウィンドウ**（既定） | `chrome.windows.create` で開き、開始URLから始めます |
| **開いているタブを指定** | そのタブで再生します。「今のページから始める」を有効にすると開始URLへ移動せず、表示中の画面から続けます |

ログインや前準備を手で済ませてから再生したい場合は、そのタブを選んでください。ポップアップの「▶ このタブで再生」からだと、対象タブが選ばれた状態で管理画面が開きます。「開始ステップ」で、手で済ませた前半（ログインなど）を飛ばすこともできます。

新しいウィンドウは通常モードの**同じプロファイル**なので、多くのものは引き継がれます。

| 項目 | 引き継がれるか |
| --- | --- |
| Cookie | されます |
| localStorage | されます |
| IndexedDB / HTTP認証 | されます |
| **sessionStorage** | **されません**（タブ単位に隔離されるため） |

Cookie ベースのログインであれば、ログイン後の画面から始まる録画もそのまま再生できます。

ただし認証トークンを `sessionStorage` に置くタイプの画面では、新しいウィンドウは未ログイン扱いになります。その場合は**ログイン操作ごと録画に含める**か、手でログインしたタブを再生先に選んでください（`sessionStorage` はタブ単位なので、同じタブで再生すれば引き継がれます）。書き出したスクリプトを CI で動かすなら、結局ログイン込みの録画が必要です。書き出したスクリプトを CI で動かす場合も、結局この形が必要になります。パスワードは記録時に `<PASSWORD>` へマスクされるので、JSON タブで実際の値に書き換えるか、`{{data.パスワード}}` として「データ」タブで管理してください。

## 実行ログ

管理画面の「📋 実行ログ」に、再生 1 回ぶんの結果が残ります。行をクリックすると各ステップの結果が開きます。

| 記録されるもの | 内容 |
| --- | --- |
| 開始・終了時刻 / 所要時間 | いつ動いて何秒かかったか |
| きっかけ | 手動 / 予定（スケジュール実行） |
| 各ステップの結果 | 成功・失敗・スキップ・任意ステップの警告、失敗時のエラー文言 |
| 代替セレクタの使用 | 本来のセレクタが外れ、別の候補で見つけた場合はその候補名 |
| ダイアログ | 再生中に出た `alert` / `confirm` / `prompt` の内容 |

新しいものから 100 件まで保存し、古いものは自動で消えます。「すべて削除」で手動でも消せます。

再生中も逐次保存しているため、**管理画面のタブを閉じても、途中までの結果は残ります**（進捗表示は消えます）。

## スケジュール実行

管理画面の「⏰ スケジュール」から、録画の自動実行を設定できます。

- **毎日この時刻に** … 例: 毎日 07:30
- **一定の間隔で** … 例: 15 分ごと

有効・無効の切り替えと削除ができ、前回の実行時刻と結果が行に出ます。結果の中身は「実行ログ」で確認してください。

制約があります。

- **ブラウザが起動している間だけ**動きます（PC がスリープしていれば動きません。復帰後に遅れて実行されることがあります）。
- 予定実行は**新しいウィンドウで開始URLから**流します。手で用意したタブは使えないので、**ログイン操作を含む録画**にしてください。
- 再生は同時に 1 本までです。実行中に別の再生を始めようとするとエラーになります。

## 検証ステップ（期待と違ったら止める）

削除や送信のように取り返しのつかない操作では、「本当に想定どおりの画面か」を確かめてから進めた方が安全です。ステップ一覧の各行にある「**＋ 検証**」ボタン、または JSON タブで足せます。

```json
{ "type": "assertText", "selector": "#msg", "value": "削除しました" }
{ "type": "assertText", "selector": "#title", "value": "受信箱", "match": "equals" }
{ "type": "assertVisible", "selector": "#result" }
{ "type": "assertMissing", "selector": "#row-3" }
```

- `assertText` … 要素の表示文字に期待した文言が**含まれる**か（`"match": "equals"` で完全一致）
- `assertVisible` … 要素が実際に見えているか（`display:none` などを弾く）
- `assertMissing` … 要素が**無い**こと（削除後に行が消えたかの確認に）

期待と違えばそのステップが失敗になり、実行ログに「期待『◯◯』 実際『△△』」として残ります。`"optional": true` を付ければ、失敗しても続行する警告扱いにできます。

## 代替セレクタ（1本外れても止まらない）

記録時、1つの要素に対して**複数の指し方**を優先順に保存しています。再生時は上から順に試すため、ページの小さな変更でいきなり止まることが減ります。

```json
{
  "type": "click",
  "selector": "a[href=\"right_main.php?mailbox=INBOX\"]",
  "selectors": [
    "a[href=\"right_main.php?mailbox=INBOX\"]",
    "div#box > table > tbody > tr:nth-of-type(1) > td > a",
    "a:text(\"受信箱\")"
  ]
}
```

優先順は「`data-testid` → `id` → `name` → `aria-label` → `href` / `value` → CSS パス（位置） → 表示テキスト」です。`タグ:text("表示文字")` は CSS ではない独自表記で、**候補がちょうど1つに絞れるときだけ**使われます（取り違え防止）。また、位置指定などが当たっている間は使われません（最後の試行でのみ有効）。

先頭以外の候補で見つかった場合は、進捗と実行ログに「代替セレクタで特定」と出ます。**その表示が出たら、本来のセレクタは既に死んでいます**。放置せず JSON タブで直してください。

`selector`（従来の1本）も併記されるため、古い録画やスクリプト出力との互換は保たれます。

## データの保存場所

録画データ・アップロードしたファイルの中身・実行ログは、いずれもブラウザのプロファイル内 IndexedDB（`webrec-db`）に保存されます。スケジュールと表示設定は `chrome.storage.local` です。外部サーバーへの送信は一切行いません。

プロファイルが壊れれば消えるため、**「全件エクスポート」で JSON を定期的に手元へ保存しておくことをおすすめします**（JSON があれば環境を作り直しても「インポート」で戻せます）。

## 対応している入力パターン

| 分類 | 対応 |
| --- | --- |
| テキスト系 input（text / email / tel / url / search / number / password） | ✓ 確定値のみ記録。パスワードはマスク |
| 日付系（date / time / datetime-local / month / week） | ✓ |
| range（スライダー）・color | ✓ |
| textarea | ✓ |
| チェックボックス・ラジオボタン | ✓ |
| select（単一・複数） | ✓ |
| **contenteditable / リッチテキストエディタ** | ✓ フォーカスが外れた時点の内容を記録 |
| **Shadow DOM（Web Components）** | ✓ `host >>> inner` 形式で記録・再生 |
| div ベースの独自ドロップダウン | ✓ クリックの連なりとして記録 |
| HTML5 ドラッグ&ドロップ | ✓ |
| **マウス実装のドラッグ・canvas への描画** | ✓ 座標の軌跡として記録 |
| **ダブルクリック・右クリック** | ✓ |
| キー入力 | ✓ Enter / Escape / Tab / 矢印 / F キー / Ctrl・Alt・⌘ との組み合わせ |
| **スクロール位置** | ✓ ウィンドウ・要素の両方 |
| ファイルアップロード | ✓ 中身ごと保存 |
| iframe 内の操作 | ✓ |
| **frameset（`<frame>`）内の操作** | ✓ 名前または位置でフレームを特定 |
| **別タブが開く操作（target="_blank"）** | ✓ 記録・再生とも新しいタブへ追従 |
| **alert / confirm / prompt** | ✓ 再生時は差し替えて自動応答（下記） |
| ページ遷移（SPA の履歴遷移含む） | ✓ |

### 補足

- **キー入力**: 通常の文字入力は記録しません（確定値を別途記録するため）。特殊キーと修飾キー付きの組み合わせのみが対象です。
- **マウス軌跡**: 8px 以上動いた場合のみ「軌跡」として記録し、単なるクリックと区別します。1操作あたり最大 300 点まで。
- **alert / confirm / prompt**: 拡張機能からはブラウザのダイアログを閉じられないため、再生中だけ `window.alert` などを差し替えて**ダイアログを出さずに**進みます。`confirm` は OK、`prompt` は既定値を返します。書き出したスクリプトでは Playwright / Puppeteer 側のダイアログ処理をお使いください。
- **Shadow DOM**: open な shadow root のみ対応します（`mode: 'closed'` は仕様上、外から辿れません）。書き出し時は Playwright なら自動貫通、Puppeteer なら `>>>` 記法になります。

### 対応していないもの

- `mode: 'closed'` の Shadow DOM
- ホバーでのみ現れるメニュー（クリックできる状態なら記録されますが、ホバー自体は記録しません）
- コピー&ペースト操作そのもの（貼り付け後の確定値は記録されます）
- ブラウザの戻る/進むボタン

## JSON がスクリプトの本体

記録内容の実体は JSON です。Playwright / Puppeteer 出力は、この JSON から生成される「書き出し形式」にすぎません。

管理画面の詳細ダイアログ →「JSON（編集可）」タブで直接編集し、「保存」でその録画に反映できます。保存前に検証され、問題があれば `steps[3].selector がありません` のように具体的な箇所が表示されます（壊れた状態では保存されません）。

**「ステップ一覧」の各行をクリックすると、JSON タブに切り替わってそのステップが選択状態で表示されます。** 先頭の「開始URLを開く」行からは `startUrl` へ移動します。直したいステップを一覧で見つけて、そのまま編集できます。

### 検証（整合性チェック）

JSON タブの「検証」ボタン（および JSON タブを開いたとき・保存時・インポート時）に、**JSON として正しいかだけでなく、シナリオとして辻褄が合っているか**を確認します。指摘をクリックすると該当ステップへ移動します。

**エラー**（これがあると保存できません）

| 内容 | 例 |
| --- | --- |
| データに無い列の参照 | `{{data.名前}}` と書いたが、データにあるのは `氏名` |
| データが無いのに `{{data.○○}}` を使用 | 「データ」タブが空 |
| セレクタとして解釈できない | `###` など |
| `timeoutMs` / `waitBeforeMs` / `ms` が数値でない・負の値 | `"timeoutMs": "abc"` |
| `navigate` の URL が http/https でない | `ftp://…` |

**警告**（保存はできますが要確認）

| 内容 | 例 |
| --- | --- |
| 未対応の変数 | `{{today}}`（そのまま文字列として入力されます） |
| パスワードが未設定のまま | 値が `<PASSWORD>` のまま |
| データの行によって列が欠けている | 1行目に `b` があり 2行目に無い |
| ステップが空 / 全ステップが無効 | — |
| 複数選択の値が空 | `"values": []` |

**情報**

- どのステップからも参照されていないデータ列
- 無効化されたステップへの `optional` 指定（効きません）

エラーの指摘には「ある列: 氏名, 年齢」のように**実在する候補が併記される**ので、打ち間違いをその場で直せます。

- **名前の変更**: 一覧の名前欄をクリックして直接編集できます（Enter で確定 / Esc で取り消し）。空の名前は保存されず、前後の空白は自動で取り除かれます。
- **エクスポート**: 詳細ダイアログの「ダウンロード」で 1 件ずつ。ヘッダーの「全件エクスポート」で全録画を 1 ファイルに。
- **インポート**: ヘッダーの「インポート」から JSON ファイルを選択。1 件形式・全件エクスポート形式・素の配列のいずれも受け付けます。既存の録画を上書きしないよう、取り込み時は常に新しい ID を採番します。

## ファイルアップロード

`<input type="file">` に対応しています。OS のファイル選択ダイアログ自体は自動化できませんが、**記録時に選んだファイルの中身を取り込んでおき、再生時に入力欄へ直接流し込む**ことで同じ状態を再現します。ダイアログは開きません。

- 記録: 普段どおりファイルを選ぶだけです。ファイル名だけでなく**中身も保存**されます（1ステップあたり合計 8MB まで）。
- 再生: 保存した中身から `File` を組み立てて `input.files` にセットし、`input` / `change` を発火します。ページ側からは利用者が選んだのと区別がつきません。
- 複数選択（`multiple`）、選択の解除にも対応しています。

**注意点**

- ファイルの中身は録画データとして IndexedDB に保存され、**JSON エクスポート時にも埋め込まれます**。機密ファイルを扱う場合はエクスポート先にご注意ください。
- 8MB を超えるファイルは中身が保存されず、検証でエラーとして表示されます。
- ドラッグ&ドロップによるアップロードは未対応です（`<input type="file">` のみ）。

**書き出したスクリプトで使う場合**

Playwright / Puppeteer はローカルのファイルパスを受け取る方式のため、出力は `setInputFiles('./files/請求書.pdf')` の形になり、必要なファイル名が先頭のコメントに一覧されます。実ファイルは、管理画面のステップ一覧にある「⭳ ○○ を保存」から取り出して `files/` に置いてください。

## 入力値に使える変数（本日日付など）

`value` や `url` に `{{...}}` を書くと、**再生のたびに実行時の値へ置き換わります**。記録した日付が固定されないので、同じ録画を毎日使い回せます。

| 書き方 | 結果の例（2026-08-27 14:05 に実行した場合） |
| --- | --- |
| `{{date}}` | `2026-08-27` |
| `{{date:YYYY年MM月DD日}}` | `2026年08月27日` |
| `{{date:YYYY}}` / `{{date:MM}}` / `{{date:DD}}` | `2026` / `08` / `27`（年・月・日が別欄のフォーム向け） |
| `{{date:M}}` / `{{date:D}}` | `8` / `27`（0埋めなし） |
| `{{date:YYYY-MM-DD\|+1d}}` | `2026-08-28`（`+1d` `-3d` `+2w` `+1m` `-1y`） |
| `{{time:HH:mm}}` | `14:05` |
| `{{datetime}}` | `2026-08-27 14:05:09` |
| `{{random:0000}}` | `0473`（0埋め4桁。`####` なら0埋めなし） |
| `{{random:1-100}}` | `57`（範囲指定） |
| `{{seq}}` | `42`（再生のたびに1増える通し番号。0埋めなし） |
| `{{seq:000}}` | `042`（同じ番号を0埋め3桁で） |
| `{{uuid}}` | `3f2b...`（ランダムなUUID） |

書式の指定は `:` の後ろ、オプションは `|` で区切ります（`{{time:HH:mm}}` のように書式中の `:` はそのまま使えます）。

**数字の書式（`{{seq}}` `{{row}}` `{{random}}` 共通）**

| 書き方 | 結果 | 用途 |
| --- | --- | --- |
| `{{seq}}` | `42` | 通常の連番（0埋めなし） |
| `{{seq:#}}` / `{{seq:####}}` | `42` | 同上（`#` は桁数を強制しない） |
| `{{seq:000}}` | `042` | 3桁に0埋め |
| `{{seq:00000}}` | `00042` | 5桁に0埋め |

`0` の個数がそのまま桁数になります。値が桁数を超える場合は切り捨てずそのまま出力されます（`{{seq:00}}` で値が 12345 なら `12345`）。

`{{seq}}` の現在値は「⚙ 設定」で確認・変更できます。1 を入れると次の再生から振り直しになります。

- 日付と連番は**1回の再生を通して同じ値**になります（画面をまたいでも年月日がずれません）。
- 未対応の変数名はそのまま文字列として残るので、意図しない置換は起きません。
- 管理画面の「ステップ一覧」には `→ 現在は "2026-08-27"` のように解決後の値が表示されます。
- **書き出した Playwright / Puppeteer スクリプトでも同じように動きます**。生成コードには同じ変換処理が埋め込まれ、`fill(V("{{date:YYYY-MM-DD}}"))` のように実行時に解決されます（変数を使っていない録画には埋め込まれません）。

## データを変えて繰り返し実行する（データ駆動）

同じシナリオを、入力値だけ変えて何度も流したい場合に使います。詳細ダイアログの「データ（繰り返し）」タブに表を登録すると、**1行につき1回シナリオを実行**します。

### 1. データを登録する

「CSV/TSV を貼り付けて取り込む」に Excel からコピーした表をそのまま貼れます（1行目が列名）。JSON を直接書いても構いません。

```json
[
  { "氏名": "山田太郎", "年齢": "30", "プラン": "pro" },
  { "氏名": "鈴木花子", "年齢": "25", "プラン": "free" },
  { "氏名": "佐藤次郎", "年齢": "41", "プラン": "max" }
]
```

### 2. ステップから列を参照する

値に `{{data.列名}}` と書くと、その行の値に置き換わります。

```json
{ "type": "input",  "selector": "#name", "value": "{{data.氏名}}" }
{ "type": "input",  "selector": "#age",  "value": "{{data.年齢}}" }
{ "type": "select", "selector": "#plan", "value": "{{data.プラン}}" }
{ "type": "input",  "selector": "#ref",  "value": "REF-{{date:YYYYMMDD}}-{{row:000}}" }
```

| 書き方 | 意味 |
| --- | --- |
| `{{data.列名}}` | 現在行のその列の値（`{{data:列名}}` とも書けます） |
| `{{row}}` / `{{row:000}}` | 何行目か（1 始まり、0埋め可） |

- 列名は**大文字小文字を区別**します。日本語の列名も使えます。
- 存在しない列を参照した場合は `{{data.○○}}` のまま画面に入力されるので、間違いにすぐ気づけます。データタブの表でも、その行に無い列は赤く表示されます。
- 各行の開始時に**開始URLへ戻ってからやり直す**ので、前の行の入力は残りません。
- 日付と `{{seq}}` は実行全体で固定、`{{row}}` だけが行ごとに変わります。行ごとに一意な値がほしい場合は `{{seq}}-{{row}}` のように組み合わせてください。
- 再生の進捗は「1/3 行目: 氏名=山田太郎 …」のように行ごとに区切って表示されます。
- 書き出したスクリプトもループになります（Playwright は行ごとに 1 テスト、Puppeteer は `for` ループ）。

## 待ち時間の設定（遅いサーバー・リロード時）

- **記録中のリロード**: ページを再読み込みしても記録は継続します（content script が読み込み時にセッション状態を問い合わせて自動的に復帰します）。ただし同一URLへのリロードそのものはステップとして記録されません。
- **自然遷移の尊重**: クリックによって既に目的の URL へ遷移していた場合、`navigate` ステップでは再遷移しません。これにより POST 結果画面などを壊しません。
- 上限を超えた場合はそのステップのみ「失敗」と表示し、後続のステップは続行します。

設定は 3 段階で解決され、下にあるものほど優先されます。

### 1. 全体設定（管理画面の「⚙ 設定」）

| 項目 | 既定値 | 用途 |
| --- | --- | --- |
| ページ読み込み待ち上限 | 60000ms | サーバー応答が遅いサイトで延ばす |
| 要素の出現待ち上限 | 8000ms | 描画が遅い画面で延ばす |
| ステップ間の待ち | 350ms | アニメーションが多い画面で延ばす |
| 失敗時のリトライ回数 | 3 | 遷移と重なった失敗の再試行回数 |

### 2. 録画ごとの設定

詳細ダイアログの「この録画の設定」タブで、項目ごとに「全体設定に従う」か「この録画だけの値」かを選べます。

- チェックを外した項目だけがこの録画の設定として保存され、残りは全体設定を引き継ぎます。
- 引き継いでいる項目は、あとから全体設定を変えれば自動的に追従します。
- 個別設定を持つ録画は、タブ名が「この録画の設定 ●2」のように表示されます。
- 「すべて全体設定に戻す」で個別設定を解除できます。

JSON タブから直接書いても同じです。

```json
{
  "startUrl": "https://example.com/",
  "settings": { "pageLoadTimeoutMs": 180000 },
  "steps": []
}
```

### 3. ステップごとの指定（特定の画面だけ遅い場合）

**待機を差し込むいちばん簡単な方法**は、ステップ一覧で行にカーソルを合わせて出てくる「＋ 待機」ボタンです。秒数を入れると、その行の**前**に待機ステップが入ります。

JSON の各ステップに直接書けます。

| キー | 意味 |
| --- | --- |
| `"timeoutMs": 120000` | このステップの要素待ちだけ延ばす |
| `"waitBeforeMs": 3000` | このステップの実行前に待つ |
| `"optional": true` | 失敗しても「警告」扱いで続行する |
| `"disabled": true` | このステップを飛ばす（削除せず一時的に無効化） |

さらに、待機専用のステップを差し込めます。

```json
{ "type": "wait", "ms": 5000 }
{ "type": "waitForSelector", "selector": "#result-table", "timeoutMs": 300000 }
```

重いバッチ処理の完了を待つ場合は、固定秒数の `wait` より、完了時に現れる要素を `waitForSelector` で待つほうが安定します。これらは Playwright / Puppeteer 出力にもそのまま反映されます。

## 既知の制限

- 記録は 1 タブが基本です。ただし `target="_blank"` などで開いた新しいタブには自動で追従します（自分で別タブに切り替えた場合は追従しません）。
- クロスオリジンの iframe は、その位置を特定できないため記録・再生が不完全になります。
- 再生は同時に 1 本までです（同じタブを取り合って壊れるため）。
- スケジュール実行はブラウザが起動している間だけ動きます。常時稼働が必要な用途には向きません。
- パスワード欄（`type="password"`）の入力値は `<PASSWORD>` としてマスクされ、実際の値は保存されません。
- セレクタは `data-testid` / `id` / `name` / `aria-label` / CSS パスの優先順で自動生成されるため、動的な DOM 構造のページでは再現性が下がる場合があります。
- 再生（リプレイ）機能は簡易実装であり、複雑な SPA やアニメーション待ちが必要なページでは失敗する場合があります。その場合は出力した Playwright / Puppeteer スクリプトを Node.js 環境で実行することを推奨します。
